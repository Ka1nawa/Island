# Security Review — Island 0.1.0

## Найдено и исправлено

### P1. Path traversal в загрузке обновления
UpdateService.DownloadAsync использовал имя ассета как имя файла. Вредоносный релиз мог прислать
имя вида "..\\evil.exe". Исправлено: Path.GetFileName, а PickAsset принимает только имена
[A-Za-z0-9 ._-]+.(exe|msi|zip). Риск регрессии низкий.

### P1. Персональные данные в скриншотах
Скриншоты содержали фон рабочего стола (вкладки браузера, страницы). Обрезаны до окна приложения;
изображения с тостами/стикерами обрезаны до самих карточек; f2_toast и v14_viz удалены.
Правило зафиксировано в CONTRIBUTING.

## Проверено, рисков не выявлено
- Секреты/токены/приватные ключи в исходниках отсутствуют (поиск по шаблонам; совпадения — имена
  переменных token/secret в коде, не значения).
- Абсолютные пути пользователя — только в winops/, который не входит в репозиторий Island.
- Зависимость одна: NAudio 2.2.1 (MIT). dotnet list package --vulnerable — уязвимых нет.
- TLS не отключается, проверки сертификатов не подавляются.
- Сетевые вызовы: Open-Meteo, LRCLIB, ICS-URL пользователя, GitHub API — только HTTPS.
- Логи не пишут содержимое календаря и токены; настройки — в %APPDATA%\Island.

## Остаточные риски
- ICS-ссылка может содержать секретный токен и хранится в открытом settings.json; рекомендуется
  не публиковать файл и использовать ссылки с ограниченным доступом.
- Windows-тосты требуют записи в HKCU (AUMID); в песочнице недоступны, вне её — не проверены.
- Обновления не подписаны; целостность проверяется только SHA-256 из описания релиза.
